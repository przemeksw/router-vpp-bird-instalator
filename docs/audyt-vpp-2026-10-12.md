# Audyt zgodności z VPP v26.06 i wpływu na pracę routera (2026-10-12)

Weryfikacja ze źródłami VPP tag `v26.06` (commit `c3200b8`). Bez kompilacji i uruchomienia na VPP — to zostaje w listach kontrolnych do labu.

## 1. Zgodność z VPP

| Obszar | Sprawdzono | Wynik |
|---|---|---|
| `startup.conf` | każde słowo kluczowe (unix, api-trace, api-segment, socksvr, memory, cpu, buffers, statseg, dpdk dev, plugins, linux-cp, linux-nl, logging) w parserach VPP | zgodne |
| `bootstrap.vpp` | `set interface mtu`, `set interface state`, `sflow sampling-rate / polling-interval / header-bytes / enable-disable`, `set ip neighbor-config ip4/ip6 limit age recycle` | zgodne |
| polecenia CLI programów | 35 poleceń `vppctl` (router-ifaces, router-fw, router-guard, router-top, instalator) — istnienie ścieżki CLI, składnia argumentów | zgodne |
| formaty wyjścia parsowane przez programy | `show interface`, `show interface address`, `show lcp` (itf-pair), `show ip6 interface`, `show acl-plugin acl` (`acl-index %u count %u tag {%s}`), `show acl-plugin interface`, `show errors` | zgodne |
| składnia ACL | `set acl-plugin acl [index N] permit\|deny src P dst P [proto N] [sport A[-B]] [dport A[-B]], … tag T`; domyślne porty 0–65535 | zgodne. Uwaga: parser VPP po nieznanym słowie przerywa (`else break`) — router-fw generuje wyłącznie poprawne słowa |
| segment statystyk | `/if/names`, `/if/rx`, `/if/tx`, `/if/rx-miss`, `/if/rx-no-buf`, `/if/punt`, `/sys/heartbeat`, `/sys/vector_rate_per_worker`, `/sys/loops_per_worker`, `/acl/<n>/matches`, `/err/<węzeł>/<powód>`, `/interfaces/<port>/<xstat>`; gniazdo `/run/vpp/stats.sock` | zgodne |
| wtyczka synack_guard | 113 identyfikatorów VPP (funkcje, makra, typy) + sygnatury kluczowych wywołań | wszystkie istnieją, sygnatury zgodne |

### Wtyczka synack_guard — szczegóły
- Tablice `clib_bihash_16_8` (IPv4) i `clib_bihash_48_8` (IPv6) w jednym pliku: v26.06 przeniósł część kodu do `bihash_template_inlines.h` ze strażnikiem dołączenia, ale `bihash_template.c` sam go zdejmuje przed każdym typem — ten sam wzorzec co `vnet/session/session_lookup.c`. Poprawne.
- Obie tablice biorą pamięć ze sterty głównej VPP (`BIHASH_USE_HEAP 1`); 4 mln + 1 mln wpisów ≈ 250 MB przy stercie 2–4 GB.
- IPv6 tworzona leniwie przy pierwszym zapisie — VPP chroni to `alloc_lock`, zapisy z wielu workerów są bezpieczne (blokada kubełka).
- Łuk `ip4-unicast` / `ip6-unicast`, `runs_before ip4-lookup / ip6-lookup`; `vnet_feature_next_u16`, `vlib_buffer_enqueue_to_next` — zgodne.
- RST: bufor przerabiany w miejscu, `vnet_buffer_offload_flags_clear`, `sw_if_index[VLIB_TX] = ~0` (FIB interfejsu wejściowego — `ip_lookup_set_buffer_fib_index`), następny węzeł `ip4-lookup`/`ip6-lookup` — zgodne.
- Proces `synack-guard-count` (`VLIB_NODE_TYPE_PROCESS`, `vlib_process_wait_for_event_or_clock`, `vlib_process_get_events (vm, 0)`) — zgodne (NULL dozwolony).

## 2. Wpływ na wydajność i ciągłość pracy

Kluczowe: polecenia CLI bez `is_mp_safe` zatrzymują wszystkie workery na czas wykonania (bariera, `vlib/cli.c`).

### Naprawione w audycie
| Problem | Było | Jest |
|---|---|---|
| router-monitor: liczniki odrzuceń karty | `vppctl show hardware-interfaces` **co 10 s** — bariera + odpytanie karty (`rte_eth_xstats_get`) | segment statystyk `/interfaces/<port>/*discard*` (VPP sam je odświeża w `dpdk-process`, bez bariery); vppctl tylko awaryjnie |
| router-guard check (co minutę w czasie ochrony) | `show errors` (bariera) | `/err/synack-guard-*` z segmentu statystyk; `show errors` tylko awaryjnie |
| `show synack-guard` | przejście po całej tablicy stanów (do 4 mln wpisów) w barierze — przy każdym wywołaniu | liczenie w tle co 10 s (proces na wątku głównym, bez bariery); `show` bez bariery (`is_mp_safe`) |
| `show synack-guard events` | bariera | bez bariery |
| router-top | 3–4 polecenia z barierą co sekundę | liczniki ze statystyk; mapa ACL co 15 s |

### Stan po audycie — co pracuje cyklicznie
| Zadanie | Co ile | Bariera |
|---|---|---|
| router-monitor | 1 s | **nie** (tylko segment statystyk) |
| router-ifaces-check.timer | 5 min | `show ip6 interface` — pojedyncze µs–ms |
| router-fw-check.timer (gdy firewall aktywny) | 5 min | `show acl-plugin acl/interface` — ms przy kilkuset regułach |
| router-guard check (gdy ochrona włączona) | 1 min | **nie** |
| router-top (gdy uruchomiony) | 1 s / mapa ACL 15 s | tylko mapa ACL |
| linux-nl (trasy BGP do FIB) | ciągle | **nie** dla tras (`is_mp_safe = 1`), krótka bariera dla zmian sąsiadów Linuksa (sesje BGP) |

### Koszt na pakiet
| Funkcja | Kiedy działa | Koszt |
|---|---|---|
| ACL router-fw | po `router-fw enable`, na interfejsach w strefach | dopasowanie acl-plugin (hash) + licznik reguły (`set counters on`; `off` usuwa licznik) |
| synack-guard | tylko w czasie ochrony (`router-guard on`) | klasyfikacja nagłówka; tablica tylko dla SYN-ACK/RST/UDP-amplifikacji do chronionych prefiksów |
| sFlow | zawsze | 1:10000 |
| statystyki | zawsze | `per-node-counters off` |

### Co może przerwać ruch / BGP (świadomie)
| Akcja | Skutek |
|---|---|
| `install-router.sh --from N` dla N ≤ 11 | etap 11 restartuje VPP, etap 12 BIRD — tylko w oknie serwisowym |
| `--from 13` | `router-ifaces apply -y` — wprowadza wszystkie niezastosowane zmiany z `ifaces.conf` |
| `--from 14`, `--from 25` | krótki restart snmpd (SNMP), ruch bez zmian |
| `--from 22`, `23`, `24` | bez przerw |
| `upgrade_script` | bez przerw (restart tylko router-monitor / router-notify) |
| `router-ifaces apply` usuwający adres | zrywa sesje BGP z tego adresu (`diff` ostrzega) |
| router-monitor `HANG_RESTART=1` | restart VPP po 30 s bez heartbeat — tylko przy prawdziwym zawieszeniu wątku głównego (linux-nl przetwarza trasy partiami 2048 z przerwami, heartbeat płynie) |
| `disable ip6 interface` przez router-ifaces | tylko na interfejsach bez adresu IPv6 w `ifaces.conf` — sesje BGP po IPv6 wymagają adresu w pliku |
